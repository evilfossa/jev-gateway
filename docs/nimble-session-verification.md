# Перевірка сесій із локальним Nimble

2–3 жовтня 2026 року шість повних сесій Codex пройшли через ізольований шлюз.
Claude Code отримав HTTP 401 від upstream; його повні сесії залишилися неперевіреними.
OpenCode не мав credentials для свого маршруту через шлюз; його сесії також неперевірені.

## Версії та сценарій

| Компонент | Перевірений стан |
| --- | --- |
| Gateway | `0.5.0`, runtime fingerprint `5e14637af2d5d3e7` |
| Ollama | `0.35.0` |
| Nimble | `nimble:latest`, Q8_0, контекст 8 192 токени |
| Model digest | `24e550a16a7081881be2f1f0d91e8cc13a597472735c04119f035a0a85c67e0c` |
| Codex | `0.160.0`, upstream `gpt-6.1-sol`, subscription Responses |
| Claude Code | `2.1.207`, запитана модель `claude-opus-4-8`; upstream відхилив login |
| OpenCode | `1.18.16`, налаштований маршрут `jev-gateway/gpt-5`; модель не запускалася |

Кожен прогін створює новий проєкт із `math.mjs` та незалежним `verify.mjs`. Початковий
`total` додає ціну товару без множення на кількість. Клієнт має прочитати обидва файли,
виправити лише `math.mjs`, запустити `node verify.mjs` і дати фінальну відповідь.
Чотири assertions перевіряють порожній кошик, кількість більше одного, дробову ціну,
нульову кількість та кілька товарів. Сценарій спочатку підтверджує, що початковий код
провалює перевірку, а після сесії повторює її та перевіряє незмінність `verify.mjs`.

Успіх вимагає завершених дій читання, редагування й перевірки, фінальної відповіді,
tool result у наступному запиті та кількох завершених запитів у шлюзі. Усі сесії Codex
завершилися з кодом `0`; кожна мала три запити через `/v1/responses` і два запити з
tool results. Усі upstream-відповіді мали HTTP 200. Пробний запуск, який виконав завдання,
але обійшов шлюз через розташування CLI-параметрів, не зарахований. Сценарій передає
параметри провайдера після `codex exec` і перевіряє фактичний трафік.

## Результати Codex

Один прогін на клітинку: дві мови × три режими. `unavailable` означає окремий локальний
endpoint із HTTP 503, а не зупинку чинного Ollama. `—` означає відсутність вимірювання.
Кількість inference включає спроби `/api/generate`, які завершилися HTTP-помилкою.

| Мова | Routing | Сесія | Час, с | LLM input | LLM output | Cached input | Local requests | Routing, мс |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Українська | on | Пройшла | 32.030 | 40 677 | 281 | 23 680 | 6 | 15 036 |
| Українська | off | Пройшла | 18.793 | 40 682 | 281 | 13 056 | — | — |
| Українська | unavailable | Пройшла | 22.532 | 40 769 | 293 | 26 496 | 3 | 3 |
| Англійська | on | Пройшла | 33.842 | 41 131 | 237 | 23 936 | 6 | 17 193 |
| Англійська | off | Пройшла | 18.587 | 40 668 | 282 | 26 496 | — | — |
| Англійська | unavailable | Пройшла | 16.032 | 40 870 | 281 | 18 176 | 3 | 3 |

З routing on кожна сесія мала два `forced` і один `none`. З routing off усі три запити
мали `passthrough` із `routing_disabled`. При недоступному endpoint усі три запити мали
`passthrough` із `jev_error: 503 from Ollama`; завдання все одно завершилося.

У цій малій вибірці середній час із routing on становив 32.936 с, без routing — 18.690 с.
Локальний вибір додав 14.246 с. Цей короткий сценарій не підтверджує виграш у вартості чи
швидкості. Один прогін на клітинку, різний стан upstream cache й порядок запусків не дають
підстав узагальнювати ці числа на довгі coding sessions.

## Завантаження моделі

На початку основної матриці Nimble вже був завантажений. Сума native `load_duration`
становила 51.051 мс для української сесії з routing on і 49.120 мс для англійської.
Native `total_duration` становила відповідно 15 021.240 і 17 182.870 мс.

Перед окремим прийнятим пробним прогоном `/api/ps` повернув порожній список моделей.
Той прогін мав 1 352.100 мс сумарного завантаження, 16 626 мс routing latency й успішно
завершився за 36.453 с. Модель не вивантажували примусово. Це спостереження природного
завантаження, а не контрольоване порівняння cold/warm startup. Воно не входить до основних
шести клітинок.

## Неперевірені сесії

| Клієнт | Мови та режими | Конкретна причина |
| --- | --- | --- |
| Claude Code | uk/en × on/off/unavailable | Початковий login був доступний у Keychain, але upstream повернув два HTTP 401. Повторний `claude auth status --json` повідомив `loggedIn=false`, `authMethod=none`. Остаточний прогін позначив усі шість клітинок `upstream_auth_absent` |
| OpenCode | uk/en × on/off/unavailable | `opencode auth list` показав 0 credentials; `OPENAI_API_KEY` відсутній. Шість клітинок мають `upstream_auth_absent_for_gateway_provider` |

Запит Claude Code із відхиленою автентифікацією містив extended thinking і prompt-cache
маркери. Шлюз обрав `hint` після двох локальних inference; переписаний запит також отримав
HTTP 401. Це підтверджує маршрут і вибір режиму, але не прийняття hint upstream, replay
thinking block або завершення сесії. Потрібен чинний upstream-login для повної перевірки.
Після відхилення початкового login додаткові ранні спроби завершувалися до запитів у шлюз;
остаточні сценарії пропущено за фактичним станом автентифікації.

Окрема перевірка `opencode debug config` у тимчасовому проєкті підтвердила default і
small model `jev-gateway/gpt-5`, base URL тестового шлюзу `/v1` і відсутність entries поза
шлюзом у поточній конфігурації. Сценарій також задає модель агента `build` для свого процесу.
Конфігураційна перевірка не замінює автентифіковану сесію чи перевірку реальних tool results.

## Повторення та ізоляція

Потрібні повний checkout, development dependencies, npm, установлені клієнти та їхня
чинна upstream-автентифікація. Спочатку створіть нову перевірену інсталяцію; обидва
каталоги у прикладі мають ще не існувати:

```bash
npm run update-local -- --prefix /private/tmp/jev-session-install-next
node --env-file-if-exists=.env scripts/verify-nimble-sessions.mjs \
  --gateway-root /private/tmp/jev-session-install-next/lib/node_modules/jev-gateway \
  --output /private/tmp/jev-session-report-next.json
```

Для підмножини доступні `--client codex`, `--language uk` і `--routing on`.
Кожна сесія обмежена 180 секундами; `--timeout-ms` змінює межу. Код виходу сценарію `1`
означає провал доступного сценарію; неперевірені через автентифікацію клітинки залишаються
явно позначеними у JSON. Development-скрипт не входить до npm-пакета.

Gateway runtime перевірено зі snapshot у новій інсталяції. Кожен тестовий сервер слухав
loopback на власному випадковому порту. Тимчасові проєкти й лише створені тестові сервери
видалені після прогонів. Спільні `current`, PID/log файли, налаштування клієнтів і процес
Ollama не змінювалися сценарієм. Моделі не вивантажувалися для вимірювань.

[Машиночитані результати](nimble-session-results.json) містять whitelist метаданих:
версії, режими, причини, тривалість, token usage та inference timings. Prompts, відповіді,
аргументи інструментів, headers і credentials не збережено. Unit-тести перевіряють цей
відбір окремо від живих сесій.
